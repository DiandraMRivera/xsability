A Simple Table

The best practices section in the main training briefly stated the formatting requirements for ‘simple’ tables. We call a table ‘simple’ if

  1. The only headers are column headers
  2. Every column header corresponds to exactly one table column

To write such a table, we “draw” it according to certain rules using spaces, pipes (e.g. |), hyphens (e.g. -), and colons (e.g. :) to specify the columns, rows, and justification, respectively. The rules are:

  1. The first row always consists of column headers
  2. The second row always defines formatting
  3. Every other row must have the same number of pipes (e.g. | ) as the first row
  4. The pipes need not be aligned
  5. The caption and cross reference go at the bottom, after one blank line.
  6. One white space must be between each piece of text and the proceeding pipe.

For example:

| Column 1 | Column 2 | Column 3 | Column 4 |
| ---: | :---: | :---: | :--- |
| Row 1 <br> Col 1 | Row 1 <br> Col 2 | Row 1 <br> Col 3 | Row 1 <br> Col 4 |
| Row 2 <br> Col 1 | Row 2 <br> Col 2 | Row 2 ....... Col 3 | Row 2  - Col 4 |
| Row 3 <br> Col 1 | Row 3 <br> Col 2 | Row 3 <br> Col 3 | Row 3 <br> Col 4 |

: A simple table {#tbl:simpletable}

is syntax for a simple table; let’s break down what it means row by row:

  1. | Column 1 | Column 2 | Column 3 | Column 4 | is a row of column headers, most boringly named “Column #”. How do we know this? Because it’s the first row of the table. THE FIRST ROW OF THE TABLE ALWAYS CONSISTS OF HEADERS.
  2. | ---: | :---: | :---: | :--- | specifies justification in the columns. --: is right justified. :-- is left justified, and :---: is center justified. THE SECOND ROW MUST ALWAYS SPECIFY FORMATTING.
  3. The rest of the table is the body. Every row has the same number of pipes as the first. Notice how the pipes are not aligned! This is okay - Pandoc will format the table for us.
  4. : A simple table {#tbl:simpletable} specifies the table “caption” (really, a title or a short descriptive blurb) and the pandoc crossref markup for making tables cross-referenceable. The single white space between {#tbl:simpletable} is required.

Such markup produces the following table:

Column 1 Column 2 Column 3 Column 4
Row 1
Col 1		 Row 1
Col 2		 Row 1
Col 3		 Row 1
Col 4
Row 2
Col 1		 Row 2
Col 2		 Row 2 ……. Col 3 Row 2 - Col 4
Row 3
Col 1		 Row 3
Col 2		 Row 3
Col 3		 Row 3
Col 4

that is cross-referenceable with @tbl:simpletable and has right and left justified first and last columns, respectively.

This is all well and good, and the world would be a lot simpler if it only needed simple tables to describe.

Complex Tables

We call a table complex if

  1. it has subheaders
  2. any cell or header corresponds to more than one column or row.

Writing such a table with Pandoc Markdown is possible using all the markup in sec. 1 and plus and equals signs (e.g. + and =), and some modifications to our rules

  1. The first row/column is the header row/column
  2. The equals sign marks the end of all column headers
  3. Table/cell corners are specified by plus signs
  4. Justification is specified with bottom corners of header row
  5. Alignment of pipes and plus signs matters
  6. One white space must be between each piece of text and the proceeding pipe, as before.

Unlike in sec. 1, the complex table we draw is the complex table we get, and formatting matters.

Example 1: Column Subheaders

For example:

+--------------+---------------------------------+
| Col 1        | Col 2                           |
|              +----------+-------------+--------+
|              | Col 2a   | Col 2b      | Col 3c |
+==============+==========+=============+========+
| Row 2        | D:       | :D          | :O     |
+--------------+----------+-------------+--------+
| Row 3        | C:       | :|          | :C     |
+--------------+----------+-------------+--------+
| Row 4        | <(**<)   | (>**)>      | <**>   |
+--------------+----------+-------------+--------+

: Our first complex table! {#tbl:firstcomplex}

is how to write a complex table in markdown. Lets see if it obeys our rules:

  1. The first row:

    
+--------------+---------------------------------+
| Col 1        | Col 2                           |
|              +----------+-------------+--------+
|              | Col 2a   | Col 2b      | Col 3c |
+==============+==========+=============+========+

    consists of only column headers even though some of those may be subheaders. We also notice that this column header row is terminated by equals signs on the bottom. Further, each cell has +’s for corners, and follows the white space rules. This row should work in a complex table

    1. The first column, on the other hand:
    +--------------+
| Col 1        |
|              +
|              |
+==============+
| Row 2        |
+--------------+
| Row 3        |
+--------------+
| Row 4        |
+--------------+

    does not have an nested headings (we will return to this), and does not have an extra markup specifying that the row cells here are indeed headers. However, it follows all of our rules. This column should work in a complex table.

I’ll leave it up to you to double check that

  1. every cell corner is denoted by a + sign
  2. all of the +’s and |’s are aligned.

The markup produces the following complex table:

Table 1: Our first complex table!
Col 1 Col 2
Col 2a Col 2b Col 3c
Row 2 D: :D :O
Row 3 C: :| :C
Row 4 <(**<) (>**)> <**>

Now, tbl. 1 is cross-referenceable using @tbl:firstcomplex, and we have made our first complex table. Disclaimer: the markdown preview enhanced window doesn’t render complex tables, because that’s Pandoc’s job. You’ll be able to see the final table int he HTML file, just like the references.

Example 2: Row Subheaders

Now, Say we wanted to add a single row header to tbl. 1. What do we do? We draw it in manually:

+----------------+---------------------------------+
| Col 1          | Col 2                           |
|                +----------+-------------+--------+
|                | Col 2a   | Col 2b      | Col 3c |
+=======+========+==========+=============+========+
|       | Row 2a | D:       | :D          | :O     |
+       +--------+----------+-------------+--------+
| Row 2 | Row 2b | C:       | :|          | :C     |
+       +--------+----------+-------------+--------+
|       | Row 2c | <(**<)   | (>**)>      | <**>   |
+-------+--------+----------+-------------+--------+

: Row headers in a complex table {#tbl:secondcomplex}

Notice how we had to “update” the rest of the table to be properly aligned - that is , pipes in-line with pipes and all corners specified by a +. This can seem a little daunting at first, but with a little practice you’ll find a way that makes sense to you.

That markup produces tbl. 2:

Table 2: Row headers in a complex table
Col 1 Col 2
Col 2a Col 2b Col 3c
Row 2 Row 2a D: :D :O
Row 2b C: :| :C
Row 2c <(**<) (>**)> <**>

which is cross-referenceable using @tbl:secondcomplex.

Example 3: Justification

Lets take the previous table and ask that

A. Column 2a right justified B. Column 2b be center justified C. Column 2c be left justified

We make the following changes:

+----------------+---------------------------------+
| Col 1          | Col 2                           |
|                +----------+-------------+--------+
|                | Col 2a   | Col 2b      | Col 3c |
+=======+========+==========+=============+========+
|       | Row 2a | D:       | :D          | :O     |
+       +--------+----------+-------------+--------+
| Row 2 | Row 2b | C:       | :|          | :C     |
+       +--------+----------+-------------+--------+
|       | Row 2c | <(**<)   | (>**)>      | <**>   |
+-------+--------+----------+-------------+--------+

: Now we're formatting! {#tbl:formatcomplex}

what did we do? We added colons next to the plus signs that terminate the column header row (a mouthful, for sure). Let’s see if we can make further sense of it:

  1. +====:+ is a right justified column. We can tell because the colon is to the right.
  2. +:======+ is a left justified column. The colon is to the left.
  3. +:-----:+ is center justified. It has colons on the left and right.

Our markup produces tbl. 3:

Table 3: Now we’re formatting!
Col 1 Col 2
Col 2a Col 2b Col 3c
Row 2 Row 2a D: :D :O
Row 2b C: :| :C
Row 2c <(**<) (>**)> <**>

which can be cross-referenced used @:tbl:formatcomplex
